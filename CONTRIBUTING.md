# Как поучаствовать

Спасибо, что заглянули! Баги, идеи и пулл-реквесты — всё пригодится. Вопросы «как настроить»
лучше задавать в [Discussions](https://github.com/ITG-Labs/sylph/discussions), а уязвимости —
только приватно, по [SECURITY.md](SECURITY.md).

## Что где лежит

Репозиторий — монорепа на Go с `go.work`: каждый сервис — отдельный модуль.

| Путь | Что |
|---|---|
| `services/core` | ядро: база, API под mTLS, оплата через ЮKassa |
| `services/agent` | агент ноды: конфиг xray, учёт трафика, heartbeat |
| `services/cron` | крон: закрывает истёкшие периоды, страхует платежи, чистит историю |
| `services/subs` | подписки: ссылки и профили для клиентов |
| `services/bot` | Telegram-бот |
| `services/panel` | панель: Go-часть и SPA на React в `services/panel/web` |
| `services/monitor` | бот алертов |
| `tools/sylph` | установщик |
| `tools/sylphca` | мини-CA для стендов и тестов |
| `pkg/` | общие пакеты: mTLS, логи, клиент API ядра, пульс, healthcheck |
| `deploy/prod` | compose-файлы ролей — их же вшивает в себя установщик |
| `deploy/test` | стенды для тестов: Postgres, xray, нода, подписки |

## Что нужно

- Go — версия из `go.work`;
- Docker с `docker compose` — для тестов с базой, xray и стендов;
- Node.js 26 и npm — только если трогаете фронт панели;
- `golangci-lint` v2 — линт.

## Сборка и тесты

```sh
make build         # собрать все модули
make test          # юнит-тесты
make vet           # go vet
make lint          # golangci-lint
make test-db       # тесты с настоящим Postgres (поднимет и погасит контейнер)
make test-xray     # тесты агента с настоящим xray
make test-node     # живой стенд ноды: Caddy, xray, агент
make test-subs     # живой стенд подписок: ядро, нода, subs и настоящие клиенты
make proto         # перегенерировать Go-код клиента xray
```

Фронт панели:

```sh
cd services/panel/web
npm ci
npm run dev        # дев-сервер
npm run typecheck
npm test
npm run build      # сборка, которую вшивает Go-бинарь панели
```

CI гоняет всё это на каждый пулл-реквест: тесты с `-race`, стенды ноды и подписок, линт каждого
модуля, сборку и фронт.

## Как мы пишем код

- Проверки — тестами рядом с кодом; новое поведение — с тестом, баг — с тестом, который его ловит.
- Ошибки не глотаем: никаких `_ =` на ошибках, которые что-то значат.
- Комментариев в коде нет — пусть говорят имена; если без пояснения не понять, лучше переименовать
  или разбить функцию.
- Секреты не попадают в логи и ошибки: токены, ключи, пароли, токены подписок.
- Тексты для людей (панель, бот, установщик, заглушки подписок) — по-русски; логи и ключи ошибок —
  по-английски.
- Новые зависимости — только если без них никак; обсудите в issue заранее.

## Коммиты

[Conventional Commits](https://www.conventionalcommits.org/ru/) на английском, заголовок до ~80
символов:

```
feat(panel): show node traffic for the last 30 days
fix(agent): keep the xray config when the core is unreachable
test(subs): cover the device limit stub
```

## Пулл-реквест

1. Сделайте форк и ветку от `main`.
2. Внесите изменения, добавьте тесты, прогоните `make test`, `make lint` и то, что затронули.
3. Если поменялось поведение деплоя или установщика — поправьте README.
4. Откройте PR: что и зачем, как проверено. CI должен быть зелёным.

Присылая изменения, вы соглашаетесь, что они распространяются под лицензией проекта —
